# bootstrap_secure_server.sh

Bash-скрипт для быстрой и безопасной настройки SSH и Fail2ban на свежем Ubuntu/Debian-сервере: помогает добавить публичные ключи, меняет порт SSH, отключает вход по паролю и включает защиту от перебора паролей — с интерактивными проверками, чтобы не потерять доступ к серверу.

## Что делает скрипт

- Интерактивно спрашивает порт для SSH (без значения по умолчанию — ввод обязателен) и проверяет его корректность.
- Проверяет наличие SSH-ключей у выбранного пользователя (по умолчанию — запустивший `sudo`, иначе `root`) и позволяет добавить один или несколько публичных ключей прямо во время запуска: валидирует формат через `ssh-keygen`, показывает отпечатки и пропускает ключи, которые уже есть в `authorized_keys`.
- Создаёт `~/.ssh` с правами `700` и `authorized_keys` с правами `600`, назначает владельцем выбранного пользователя и при необходимости делает резервную копию файла.
- Обновляет систему и устанавливает `mc`, `fail2ban` и `python3-systemd` (нужен fail2ban для `backend = systemd`).
- Делает резервные копии изменяемых конфигов перед изменением.
- Обходит особенность Ubuntu 22.10+/24.04, из-за которой смена порта SSH требует полной перезагрузки сервера.
- Пишет параметры SSH в drop-in `/etc/ssh/sshd_config.d/00-secure-setup.conf` (новый порт, вход только по ключу, запрет пустых паролей); на старых системах без `Include` — правит `sshd_config` напрямую.
- Если установлен `ufw` — разрешает новый SSH-порт до перезапуска SSH (защита от блокировки доступа).
- Проверяет синтаксис конфигурации (`sshd -t`) перед перезапуском службы и подтверждает, что SSH слушает новый порт, после него.
- Настраивает `fail2ban` с эскалацией времени бана, добавляет IP текущей сессии в `ignoreip` (защита от самобана) и перезапускает его.
- В конце показывает сводку и статус служб.

## Требования

- Ubuntu (проверялось на версиях с systemd socket-активацией SSH — 22.10 и новее, включая 24.04) или Debian с `apt` и `systemd`.
- Запуск от root (`sudo`).
- **SSH-ключ** — уже добавленный в `~/.ssh/authorized_keys` или подготовленный, чтобы вставить его на шаге 3. Скрипт отключает вход по паролю, поэтому без ключа у выбранного пользователя настройка не продолжится и вы рискуете потерять доступ.
- Интерактивный терминал — скрипт нельзя запускать через pipe, `cron` или без TTY (он специально завершится с ошибкой, а не выберет порт сам).

Скрипт не тестировался на RHEL/CentOS/Fedora (там другой пакетный менеджер и служба называется `sshd`, а не `ssh`).

## ⚠️ Перед запуском

Желательно заранее убедиться, что можете зайти на сервер по ключу:

```bash
ssh -i ~/.ssh/id_ed25519 user@server
```

Если ключа на сервере ещё нет, его можно вставить на шаге 3 — скрипт добавит его в `authorized_keys` выбранного пользователя и выставит права. Проверка наличия ключей привязана к выбранному пользователю (по умолчанию — запустивший `sudo` или `root`), а не ко всем аккаунтам сразу: ключи root не считаются защитой для `ubuntu`. Если ключей так и не найдётся, скрипт остановится и не будет отключать вход по паролю.

## Использование

```bash
chmod +x bootstrap_secure_server.sh
sudo ./bootstrap_secure_server.sh
```

Скрипт запросит порт для SSH и проведёт через 9 шагов настройки, показывая прогресс и результат каждого шага.

## Пошаговый процесс

| № | Шаг | Что происходит |
|---|-----|-----------------|
| 1 | Проверка прав доступа | Скрипт должен быть запущен от root |
| 2 | Выбор порта SSH | Запрашивает порт (1-65535), предупреждает про порт 22 и порты <1024, проверяет занятость порта |
| 3 | Проверка и добавление SSH-ключей | Проверяет ключи у выбранного пользователя (по умолчанию — запустивший `sudo`, иначе `root`); предлагает добавить новые (по одному, пустая строка — закончить), проверяет формат и пропускает дубликаты; без ключей останавливается |
| 4 | Обновление и установка пакетов | `apt update && apt upgrade`, установка `mc`, `fail2ban` и `python3-systemd` |
| 5 | Резервное копирование | Копия `00-secure-setup.conf` (при повторном запуске) или `sshd_config` (fallback) с суффиксом `.bak.<дата-время>` |
| 6 | Отключение socket-активации SSH | При наличии `ssh.socket` переводит SSH в обычный режим службы (см. раздел ниже) |
| 7 | Настройка параметров SSH и фаервола | Пишет порт и параметры аутентификации в drop-in `00-secure-setup.conf` (или в `sshd_config` на старых системах), проверяет конфиг (`sshd -t`), разрешает порт в `ufw`, перезапускает SSH и подтверждает, что он слушает новый порт |
| 8 | Настройка Fail2ban | Создаёт `jail.local` с IP текущей сессии в `ignoreip`, перезапускает и включает автозапуск |
| 9 | Проверка состояния служб | Показывает статус `ssh`, `fail2ban` и jail `sshd` |

## Добавление SSH-ключей

На шаге 3 скрипт предлагает добавить публичные ключи, даже если ключи уже есть — например, чтобы добавить резервный.

- Аккаунт по умолчанию — пользователь, запустивший `sudo` (`$SUDO_USER`), иначе `root`. Имя можно изменить при вводе; скрипт проверит, что пользователь существует и у него есть домашний каталог.
- Проверка защиты от блокировки выполняется по фактическому `authorized_keys` этого пользователя, а не по любому найденному файлу: ключи, добавленные только root, не считаются защитой для `ubuntu`, и наоборот.
- Если у выбранного пользователя так и нет ключей, скрипт завершается до изменения конфигурации SSH — продолжить без ключей нельзя.
- Ключи вставляются последовательно, по одному: после каждого сразу выполняется проверка, показывается отпечаток, и только потом запрашивается следующий. Пустая строка завершает ввод.
- Формат строки — обычный публичный ключ без опций: `ssh-ed25519 AAAA... user@host`. Поддерживаются RSA, ECDSA, Ed25519 и SK-ключи; корректность проверяется через `ssh-keygen`.
- Дубликаты определяются по типу и содержимому ключа, а не по комментарию: ключ с тем же блобом, но другим комментарием или с опциями в `authorized_keys` будет пропущен.
- Скрипт создаёт `~/.ssh` с правами `700`, `authorized_keys` — `600`, назначает владельцем выбранного пользователя и перед первым изменением файла делает резервную копию.
- Если домашний каталог пользователя доступен на запись группе или остальным, скрипт предупредит: `StrictModes` в sshd может отклонить ключ. Исправление — `chmod go-w <home>`.

## Итоговые параметры SSH

На современных системах все параметры пишутся одним drop-in-файлом `/etc/ssh/sshd_config.d/00-secure-setup.conf`; основной `sshd_config` не изменяется.

| Параметр | Значение |
|---|---|
| `Port` | выбранный вами порт |
| `PubkeyAuthentication` | `yes` |
| `PasswordAuthentication` | `no` |
| `PermitEmptyPasswords` | `no` |

## Итоговые параметры Fail2ban (`jail.local`)

| Параметр | Значение |
|---|---|
| `bantime` | 30 минут, удваивается с каждым повторным баном (`bantime.factor = 2`), максимум 24 часа |
| `findtime` | 10 минут |
| `maxretry` | 3 попытки |
| `backend` | `systemd` |
| `ignoreip` | `127.0.0.1/8 ::1` + IP вашей текущей SSH-сессии (если удалось определить) — этот IP не банится |
| jail `sshd` | включён, слушает выбранный порт; логи берутся из systemd journal (`backend = systemd`) |

## После запуска — обязательно проверьте доступ

Скрипт сам об этом напомнит и покажет готовую команду с актуальным пользователем, но это критично: **не закрывайте текущую SSH-сессию**. Откройте новое окно терминала и проверьте новое подключение:

```bash
ssh -p <ваш порт> <пользователь>@server
```

Только убедившись, что новое подключение работает, закрывайте старую сессию.

Полезные команды после установки:

```bash
fail2ban-client status sshd              # список забаненных IP
fail2ban-client set sshd unbanip <IP>    # разбанить IP
```

## Резервные копии и откат

Перед изменениями скрипт копирует с суффиксом `.bak.ГГГГММДДЧЧММСС` только то, что собирается менять:

- `/etc/ssh/sshd_config.d/00-secure-setup.conf` — при повторном запуске, когда drop-in уже создан
- `/etc/ssh/sshd_config` — только в fallback-режиме (на старых системах без `Include`)
- `/etc/fail2ban/jail.local` — если существовал до запуска
- `~/.ssh/authorized_keys` выбранного пользователя — если скрипт добавлял в него ключи

`50-cloud-init.conf` и остальные провайдерские файлы скрипт не трогает.

Откат SSH-параметров в обычном (drop-in) режиме — достаточно удалить drop-in и перезапустить SSH:

```bash
sudo rm /etc/ssh/sshd_config.d/00-secure-setup.conf
sudo systemctl restart ssh
```

Либо скопируйте нужный `.bak.*`-файл обратно поверх оригинала и перезапустите соответствующую службу.

## Технические детали

**Drop-in `00-secure-setup.conf` и first-match-wins.** `Include sshd_config.d/*.conf` стоит в начале `sshd_config`, а sshd применяет первое вхождение каждого параметра. Поэтому провайдерский `50-cloud-init.conf` (например, с `PasswordAuthentication yes`) обычно перебивает правки в основном файле. Drop-in с именем `00-` сортируется раньше всех остальных `.conf` — его значения побеждают всё остальное. На старых системах, где `Include` не используется, скрипт правит `sshd_config` напрямую.

**Socket-активация SSH (Ubuntu 22.10+/24.04).** На современных Ubuntu SSH по умолчанию запускается через systemd socket-активацию: слушающий порт держит юнит `ssh.socket`, а не сам процесс `sshd`. Из-за этого обычный `systemctl restart ssh` не применяет новый `Port` из `sshd_config` — требовалась полная перезагрузка сервера. Скрипт обнаруживает этот случай и переводит SSH в классический режим (`systemctl disable --now ssh.socket && systemctl enable --now ssh.service`), как рекомендует `README.Debian` пакета `openssh-server` — после этого порт применяется обычным перезапуском, без перезагрузки.

**Защита от блокировки доступа (lockout).** Перед перезапуском SSH скрипт разрешает новый порт в `ufw` (если он установлен — правило сохранится, даже если фаервол сейчас неактивен). После перезапуска он проверяет через `ss`, что sshd действительно слушает новый порт. В финальном предупреждении напоминает про облачные фаерволы (Hetzner Firewall, AWS Security Group) — порт нужно открыть и там.

**Проверка конфигурации перед перезапуском.** Перед `systemctl restart ssh` скрипт выполняет `sshd -t`. Если в конфиге ошибка, перезапуск не выполняется — это защита от потери доступа из-за опечатки.

**Обязательный интерактивный ввод порта.** У порта нет значения по умолчанию: пустой ввод отклоняется, а без интерактивного терминала скрипт завершается с ошибкой вместо того, чтобы выбрать порт самостоятельно.
